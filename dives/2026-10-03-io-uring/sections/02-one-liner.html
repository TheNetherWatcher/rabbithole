"io_uring is async I/O via two shared ring buffers, so you skip syscalls."

Hides:

  1. Most ops are not async: the kernel first tries the op inline, non-blocking in submit context. Async is the fallback, and for buffered file I/O the fallback is a thread pool (io-wq), not hardware async.
  2. "No syscalls" is only true with SQPOLL (burns a core); otherwise one io_uring_enter per batch. Win = amortization.
  3. Naive port gains about nothing (measured: 1.06x buffer mgr, 1.10x shuffle). Gains come from batching + registered resources + task-work control + redesigned architecture.
  4. It is a second syscall interface: ops live in SQEs, invisible to seccomp/syscall audit. Google disabled it on ChromeOS/prod.
  5. Zero-copy isn't free: ownership of buffers/cancellation is the hard part; ZC send loses to memcpy for small payloads [K].

Jasny et al. compare a naive swap with a redesigned io_uring path in a buffer manager and a network shuffle. The naive swap barely moves; the redesign does the work.
