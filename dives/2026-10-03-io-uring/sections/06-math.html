Amortization

Let cs = enter syscall cost, co = per-op in-kernel work, B = ops per enter.

cost/op = cs / B + co→ in plain terms: batching divides the fixed cost. Jasny et al. measure 5-6× fewer cycles/op at B ≥ 16 [V] arXiv 2512.04859. The limit B→∞ gives co: you can't beat it, which is why SQPOLL/polling matter only when cs/B is still visible.

Little's law for queue depth

IOPS = QD / latency→ in plain terms: 100 µs NVMe read, 1M IOPS ⇒ QD = 100. Sync I/O has QD=1 per thread ⇒ 10K IOPS/thread. Jasny's synchronous POSIX baseline 16.5K tx/s vs 376K tx/s with io_uring (buffer manager, 1 thread) is mostly QD, not syscall cost. Batching isn't the only win; concurrency in one thread is.

Ring index arithmetic

head, tail are free-running u32. used = tail − head (mod 232), free = N − used, slot = idx & (N−1) (N power of 2).

used = (tail − head) mod 232; free = N − used; slot = idx & (N−1)→ in plain terms: Why free-running instead of wrapping at N: full vs empty are distinguishable (used==N vs 0) with no spare slot or flag; all N slots are usable. Correct across u32 overflow because of modular subtraction.

Memory-ordering contract (SQ)

App: write SQE; store_release(tail). Kernel: load_acquire(tail); read SQE. The release→acquire edge ⇒ SQE writes happen-before kernel reads. The kernel consumes with smp_store_release(sq.head) (seen in io_commit_sqring [V]); the app load_acquire(head) before reusing a slot. CQ mirrored. Without release on tail, the CPU/compiler could expose tail before the entry bytes ⇒ the kernel reads a garbage SQE. (CQ-side acquire/release pairings are inferred from paper + liburing, not read from source.)

CQ overflow bound

Pending requests can exceed SQ size (SQE consumed ⇒ slot reusable, request still in flight). In-flight P ≤ SQ_entries + inflight_async; CQ = 2×SQ by default doesn't bound P. Hence NODROP (5.5): overflow CQEs are held in a kernel list, flushed on next enter(GETEVENTS); a purely userspace CQ poller can stall forever.
