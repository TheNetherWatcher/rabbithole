Most of the time, nothing runs. A trading firm's hot path runs about 0.01% of the time, so it is cold by default. It still has to be fast on the one call that matters, every time.

The naive way: let it go cold. After the cache is flushed, the path takes p50 542 ns. Warm, the same path takes 84 ns. That is 6.5× at the median, and the gap is cache misses.

The fix: a dummy tick. Every few µs to ms, a synthetic tick runs the full path with dry_run set. The book, the parameters and the branch predictor stay trained, and no order goes out.

One packet, no syscalls. The NIC writes the frame into a ring the thread is already polling. The message is parsed in place, and the book update takes about 10 ns in our lab.

Then the decision. The strategy compares the best ask with its trigger, and the risk check is a single branch on one flag word. The order is built from preallocated memory.

The budget. A very good wire-to-wire time for a software trading system is about 2.5 µs. One deep core C6 exit costs about 90 µs, so a single stall is far over the whole budget.

The trap: false sharing. Two counters on one cache line make every write move that line between cores. In our lab, the shared layout ran 23× slower than the padded one.

Speed is not enough. Knight Capital lost over $460M in 45 minutes when a reused flag woke dead code on one of eight servers. Automated, blocking risk gates are what keep fast code safe. The cards below take each piece in turn.
