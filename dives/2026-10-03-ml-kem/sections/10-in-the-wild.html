• AVX2 / AVX-512 implementations merge NTT layers, use signed Montgomery (R = 2^16, QINV = −3327) and Barrett (v = 20159) reduction with lazy reduction across layers, and vectorize rejection sampling. Seiler's AVX2 NTT made polynomial multiplication 6.3× faster (ePrint 2018/039). The reference code stores zetas in Montgomery form, and the inverse NTT finishes with a scale of 1441 = mont²/128.
  • libcrux (Cryspen): Rust verified with hax→F for panic freedom, functional correctness and secret independence. Extracted to C, it ships in Firefox/NSS and OpenSSH*. It warns that compiled binaries aren't verified side-channel free. Its verification work found KyberSlash.
  • mlkem-native (PQ Code Package, AWS): C proven memory-safe and overflow-free with CBMC. AArch64 and x86-64 assembly proven correct and constant-time in HOL Light. AArch64 code superoptimized with SLOTHY, which sits outside the trusted computing base because the proofs don't depend on scheduling. Gives 2.0–2.4× over the reference code in AWS-LC. Default ML-KEM in liboqs 0.13+ (repo, Amazon Science).
  • Jasmin / libjade + EasyCrypt: a machine-checked IND-CCA proof of ML-KEM linked to a constant-time x86 implementation that is about as fast as unverified AVX2 code (CRYPTO 2024, ePrint 2024/843).
  • Go crypto/mlkem (Filippo Valsorda): written from scratch against the spec, about 500 lines, specialized encoders for 1/4/10/12 bits, Barrett reduction without division, seed-only keys. Now inside the FIPS 140-3 Go module (blog).
  • Private keys: BoringSSL, Go and RFC 9935 recommend the 64-byte seed over the 2400-byte expanded key. OpenSSL keeps both by default (seed-priv) because HSMs often only hold expanded keys.
  • TLS byte order: X25519MLKEM768 puts ML-KEM first (mlkem ‖ x25519). The NIST-curve hybrids put ECDHE first. The draft codepoint 0x6399 used the opposite order.
  • Signal SPQR: uses the fact that the 960-byte part of an ML-KEM-768 ciphertext depends only on ρ and the randomness, not on t, so the sender can start once a 64-byte header arrives. Keys and ciphertexts are erasure-coded into chunks (37 and 34) that ride on ordinary messages (Signal).
