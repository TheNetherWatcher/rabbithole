Every flush writes its buffer to disk as one sorted run. A merge rule decides when those runs combine. Both rules below start from the same trace, with size ratio T = 3.

Leveling, the naive way. Each flush merges into the one run that sits on L0. Reads stay quick because there is only one run to check, but the old data gets copied every time.

Flush 2 rewrites 1 unit. The resident run is read and written again just to absorb one new unit of data.

Flush 3 rewrites 2 units. The run keeps growing, and every arrival pays to copy all of it again.

Flush 4 pushes the run down. The run passes L0's limit and moves to L1. That merge rewrote 3 units, and the bytes it moved were already sorted once.

The rule. Under leveling, each entry is re-merged about (T−1)/2 times per level. At T = 3 that is one time. The count grows with T, so bigger ratios make leveling costlier to write.

Tiering waits. Each level holds up to T runs instead of one. Runs stack on L0, and nothing is rewritten until the third one arrives.

Then one merge. The three runs merge once into L1, so each entry is written about once per level. The price moves to reads: a lookup may probe up to T − 1 = 2 runs per level, unless a Bloom filter says no.
