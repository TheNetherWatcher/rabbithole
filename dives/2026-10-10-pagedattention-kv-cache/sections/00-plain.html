Picture a busy restaurant with one long bench. When a party walks in, the host doesn't know how long they'll stay or how many friends will join later. So the cautious host blocks off enough bench for the biggest party that could possibly arrive, maybe 20 seats for a group of 3. The bench fills with empty "reserved" seats, and new guests wait outside while the room is two-thirds empty.

A large language model has the same problem with its working memory. While it writes an answer, it keeps a running notebook of everything said so far (the "KV cache"), and that notebook grows by one line per word. Older servers set aside one solid stretch of GPU memory per conversation, sized for the longest possible answer, and most of it sat empty. PagedAttention swaps the bench for small four-seat tables. A party gets one table, takes another when it fills up, and the tables don't have to be next to each other. A little card (the "block table") records which tables belong to which party. Nearly every seat ends up in use, so the GPU serves two to four times as many conversations at once.

Everyday example

Maya asks a chatbot: "Write a haiku about rain." That's 7 words of question. Tables seat 4, so her notebook needs 2 tables: table #7 holds words 1–4 and table #1 holds words 5–7, with one seat free. The model writes "Soft", which lands in that free seat. Now table #1 is full. When it writes "drops", the host grabs any free table (#3, across the room). Maya's card reads 7 → 1 → 3.

A minute later Maya's friend asks the same question with "give me two versions". Both versions share tables #7 and #1. Only when version 2 needs to write somewhere different does it get its own copy of the last table. When Maya finishes, her tables are wiped and handed to the next guest straight away.
