A large target model writes one token at a time, and each token needs a full pass over its weights. Chinchilla 70B on 16 TPU v4 takes 14.1 ms per token with plain sampling.

The naive way is serial. Token t+1 cannot start before token t exists. At batch 1, a 70B model reads about 140 GB of weights for each token, while the compute units sit mostly idle.

The key idea: a cheap drafter writes three guesses ahead. The drafter is a small model, or a few heads on the target itself.

The target then scores all three guesses in one pass. Scoring known tokens is parallel, so at small k it costs about the same as one decode step.

Each guess is checked with min(1, p/q). "mat" has p 0.60 and q 0.50, so it is kept. "and" has p 0.10 and q 0.40, so it passes with probability 0.25. The draw of 0.83 is above that, so it fails, and "purred" goes with it.

The target writes a replacement for "and" itself, sampled from the leftover mass max(0, p − q). Here it is ".", because the drafter had already over-proposed "and".

Two new tokens came out of one target pass: "mat" and ".". Had all three guesses passed, a fourth token would have come free from the target.

The trick spends spare compute. Once batches are big, there is none left. EAGLE-3 on an 8B model in vLLM falls from 1.75× at batch 2 to 1.01× at batch 56 on an RTX 3090.
