One server does 100 requests a second. Users send 70 a second, so the queue stays short and every request is served. Each user waits up to 1 s, and if nothing comes back, sends again, up to two times.

The trigger. For 10 seconds, from t = 20 s to t = 30 s, the server does no work. Requests keep arriving and pile up behind it, to about 1,870 by the time it comes back.

The naive way. Every request that waits longer than 1 s times out and is sent again. Each user request now costs 3 attempts, so 210 a second reach a server that does 100. The old copy stays in the queue.

The stall ends, the queue does not. At t = 40 s the queue holds 2,971 requests. The server takes the oldest first, and those clients left long ago, so each request it serves is wasted work.

The loop keeps it going. Arrivals run at 210 a second and capacity at 100, so the queue grows by about 110 a second. At t = 60 s it holds 5,191. The trigger is no longer needed to keep it that way.

Still stuck. At t = 120 s the queue holds 11,826, and the server is 100% busy with 0 goodput. A fresh attempt now waits about 30 s for a 1 s timeout.

The fix: skip the dead work. Drop each request whose client has already left, as soon as it is dequeued. Skipping costs nothing, and goodput is back at 70 a second when the stall ends at t = 30 s. Serving the newest request first does the same.

Or cut the retries. With no retries the queue drains and the system is healthy again at t = 51 s. A retry budget of 10% gets there by t = 64 s. Each fix removes one leg of the loop.
