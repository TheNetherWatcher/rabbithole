A hash table has to answer "where is this key?" fast. The classic answer, chaining, hashes to a bucket and walks a linked list. It works, but every hop is a pointer to a separately allocated node, so a lookup is a string of likely cache misses and every entry pays for a pointer.

Open addressing drops the lists. Keys and values sit directly in one flat array of slots, grouped here in rows of 8 (Abseil uses 16). A key hashes to a home group and goes in the first free slot it finds. No pointers, no per-entry allocation. The price: a lookup now has to check slots, and a full key comparison per slot is expensive.

The trick: a tag per slot. Next to the slots, keep a separate array with one byte per slot. A full slot stores 7 bits of the key's hash. An empty slot stores a special "empty" value. The tag is a cheap fingerprint: slots whose tag differs cannot hold the key.

One instruction checks a whole group. Load the group's tag bytes into a SIMD register, compare all of them to the key's tag at once, and get back a bitmask of candidates. Here two slots match 5A. Only those get a real key comparison. A wrong tag matches roughly 1 slot in 128, so false matches are rare.

Empty is the stop sign. If the group holds no match and at least one empty slot, the key cannot be further along, because inserts always fill the earliest free slot on the probe path. If the group is completely full, the probe hops to another group, +1 then +2 then +3 groups (triangular steps), and repeats.

Deleting needs care. Emptying a slot in a full group could cut a probe path that once passed through it, so such a slot gets a tombstone marker that says "keep going". If the group already has an empty slot, no probe ever passed it, and plain empty is safe. That check keeps tombstones rare.

The result. Tables run at up to 7/8 full, spend one byte of metadata per slot and scan 16 slots per instruction. Rust's HashMap, Go's built-in map since 1.24 and Google's Abseil all use this layout. The cost: values move when the table grows, and tombstones can pile up until a rehash.
