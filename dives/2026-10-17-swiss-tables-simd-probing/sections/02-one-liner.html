The one-liner: "An open-addressing hash table with a 1-byte tag array, so one SIMD compare checks 16 slots at once."

What it hides

  1. The tag is only 7 bits, so false matches happen (about 1 per 128 occupied slots) and the full key is always compared before a hit is declared.
  2. The control byte has three states besides a tag: empty, deleted, sentinel. Whether a slot is empty or deleted decides if a probe stops, and getting it wrong breaks lookups.
  3. Probing is per group, not per slot, in triangular steps, and which groups get visited depends on how many are full: at 7/8 load, nearly half of 16-slot groups have no empty slot.
  4. Erase sometimes writes empty instead of a tombstone, using a "was this slot ever in a full window" test. That one trick is what keeps churn workloads from filling the table with tombstones.
  5. The 7/8 load factor is only affordable because a group probe is cheap. Go and hashbrown chose different group widths and added different growth machinery around the same core.
